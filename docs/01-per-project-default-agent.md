# Workplan: Per-project default agent

> System of record: **Filesystem**

## Objective

Add a project-level agent preference in Project Settings. An explicit launch choice must always win; otherwise Orca should use the owning project's preference, then the global Settings → Agents preference, then the existing detected-agent fallback. The project may explicitly choose Blank Terminal, while an unset value inherits the global preference. Keep Source Control AI recipes, saved automation agents, continuation choices, and other explicitly configured action agents independent. Preserve the preference for git and folder projects across project identity changes and execution hosts, and degrade safely with mixed-version remote Orca servers.

## Action Plan

1. [ ] Define the shared preference contract and resolution helpers: persist an optional project default (`TuiAgent | 'blank'`, absent means “inherit global”), use an explicit clear value in update commands so JSON/RPC can represent inheritance, and centralize precedence as explicit launch choice → valid project preference → valid global preference → existing detected-agent auto-pick. Retain unavailable project choices instead of deleting them; show their status and fall back safely on a host where they are disabled or not detected.
2. [ ] Extend `Project` and `ProjectUpdateArgs` in `src/shared/project-types.ts`, normalize untrusted project rows, and update IPC/RPC schemas so the new field is optional on reads and explicitly clearable on writes. Add a static runtime capability for remote project-default-agent writes because an older server would otherwise strip the unknown update and appear to save it; newer clients should disable the remote control with an update-required message when that capability is absent.
3. [ ] Persist and preserve the new field through `project-host-operations.ts`, project projection regeneration, `carryProjectStateThroughIdentityChange`, renderer host-catalog merges, and update-result merges. Add deterministic tests for set, replace, clear/inherit, restart hydration, repo→git→provider project-ID promotion, folder projects, multiple host projections, and newer-client/older-server behavior.
4. [ ] Add a Project Settings “Default agent” control near the project identity/runtime defaults, reusing the existing agent catalog and shadcn selection patterns rather than restyling a primitive. Offer “Inherit global (<effective agent>)”, “Blank Terminal”, and enabled detected agents for the selected project host; preserve and label a configured agent that is unavailable on that host. Include searchable settings metadata, concise helper text explaining precedence, immediate disabled state while a remote save is pending, inline persistent save errors, and mixed-version/update-required copy.
5. [ ] Introduce one renderer selector that resolves the owning logical project from a repo/worktree/folder workspace and returns its effective agent preference. Replace direct global-default reads on contextual launch surfaces: the new-agent shortcut, tab-bar ordering/default badge, Quick Launch, floating-workspace launch, dashboard launch options, and new-workspace composers after a project/repository is selected. Keep explicit picker selections and per-agent shortcuts unchanged.
6. [ ] Apply the same resolver to implicit task/work-item and worktree startup paths, including draft-seeded workspace creation and runtime-owned startup, by resolving the project on the execution host before choosing an agent. Preserve explicit `startupAgent`/`createdWithAgent`/action recipe choices, the project `blank` behavior, disabled-agent filtering, SSH detection, and folder-workspace routing. Do not make Source Control AI or saved automation agent settings inherit this value unless their existing contract currently delegates to the ordinary workspace default.
7. [ ] Cover behavior with focused unit/component/runtime tests: precedence and unavailable-agent fallback; Project Settings set/clear/error/capability states; local, SSH, paired-runtime, WSL, and folder-workspace resolution; shortcut/menu/dashboard/composer consistency; explicit launch overrides; blank-terminal suppression; and project identity/host refresh stability. Add a regression assertion that global Settings → Agents remains unchanged when editing a project default.
8. [ ] Run `pnpm tc`, targeted Vitest suites for project persistence/RPC/settings and each changed launch surface, `pnpm run check:code-quality:changed`, and `pnpm format`. For UI validation, rebuild affected launch code and run Orca only with `ORCA_BACKGROUND_LAUNCH=1`; use Playwright CDP screenshots of hidden renderers to verify Project Settings in light/dark themes and the effective default on local and remote-host project contexts without showing or focusing windows.
